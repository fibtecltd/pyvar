Usage

Three commands to get started

# load the image
$ docker load -i pyvar-local.tar.gz
Loaded image: pyvar-local:<sha>

# browse the 385 functions
$ docker run --rm pyvar-local:<sha> list

# call one
$ docker run --rm pyvar-local:<sha> call \
  montecarlo run_monte_carlo_var \
  --params '{"n_simulations": 1000, ...}'
1
Load, don't run, the tarball directly
docker load prints the exact tag it loaded — use that tag (not a bare pyvar-local with no tag) for every command after. Optionally re-tag it shorter: docker tag pyvar-local:<sha> pyvar-local:local.
2
Every function is reachable by name
The CLI reflects over the actual engine/ modules at runtime, so it can't drift out of sync with what the image actually contains — the same 385 functions as the hosted API, across all 8 domains.
3
Verify it yourself — the test suite ships too
Run the same numerical-correctness suite that gates the hosted platform, inside your own copy of the image: docker run --rm --entrypoint pytest pyvar-local:<sha> /app/tests/test_engine.py -v.
Scope

What's in this first release

Included
  • ✓ The exact same compute engine that powers the hosted pyvar.com API — packaged from the same source on every release, never a manually-maintained fork.
  • ✓ The numerical-correctness test suite (tests/test_engine.py), shipped so you can run it yourself, not just take it on trust.
  • ✓ A minimal CLI covering all 385 functions across all 8 domains, generated by reflecting over engine/ at runtime.
Not yet in it
  • – A full local FastAPI server matching the hosted API's route surface (auth, per-function REST endpoints, request/response schema validation) — tracked as a fast-follow, not a gap in this release.
  • – A signed licence file, regulatory documentation bundle, or update/support SLA — the commercial packaging around this artifact is a separate, later decision, not bundled with this one-off share.
